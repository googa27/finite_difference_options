# Compiled adapter extraction

Issue #175 is a structural prerequisite for #170. The released module stays `finite_difference_options.integrations.compiled_pde_adapter`. Immutable DTOs/constants and strict validation have cohesive private modules; fixture loading, top-level screening and solve orchestration remain in the public module. Four DTO/error classes retain their original `__module__` values. All 30 original adapter class/function ASTs are preserved. The verification module also delegates its seven unchanged grid/refinement/residual helpers to `validation/fd_evidence/grid_metrics.py`; its public functions, constants and historical private aliases remain available. All original verification definition ASTs are unchanged. No numerical implementation, replay schema, dependency or default changes.

The checked-in compatibility fixture was captured before extraction from a clean wheel built at `c85b40378dda19e51f0b7e9352aa23edc9cd9ac0`. It records the nine explicit adapter exports, verification exports/constants, callable signatures, module identities, exact supported screening JSON and trusted synthetic protocol-4 pickle bytes. The compatibility test checks these independently captured observations against source and installed wheels. Only these repository-owned fixture bytes are unpickled; arbitrary pickle input is not an API.

Authentic numerical v0 evidence and solve outputs were also captured from that clean wheel under Python 3.12.3, NumPy 2.5.3 and SciPy 1.18.1, with BLAS/OpenMP threads limited to one. They are compared byte-for-byte in the implementation review packet. This is same-runtime preservation evidence, not a claim that dense LAPACK roundoff is identical across environments. The numerical solver and verification implementations are unchanged by this extraction, and the existing analytic/negative-control tests remain the mathematical acceptance gates.

The future v1 numerical work must be explicit opt-in, retain the no-argument and CLI v0 route, and define replay/version compatibility. This extraction makes no v1 consumer-support claim.
